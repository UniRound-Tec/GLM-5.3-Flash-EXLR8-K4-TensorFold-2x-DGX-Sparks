# Retained prefill update — 2026-10-19

This update packages the source and settings already tested on two DGX Sparks. Packaging itself does not run inference, restart the online service, or resume the completed experiments.

## Implementation

- `qmm.py`: 14 exact-shape BF16 Triton configurations; mode 3 additionally selects 18 `(M, N, K, FP32-output)` shapes for cuBLAS. Both TP slices passed the numerical threshold and a local speed screen before inclusion. BF16 operands, FP32 accumulation, original output dtype, and existing decompression storage are retained. Reduced-precision BF16 reduction is disabled around the selected call and the previous flag is restored afterward. Small inputs and unmatched shapes keep their existing paths.
- `trial_control.py`: request-boundary `bf16_prefill`, `prefill_pieces`, and `prefill_schedule` selection, TP payload compatibility, and prefix-cache path separation. The retained schedule keeps HC rank partitioning but processes input/output projection matrices as whole row batches; output exchange no longer overlaps fragmented projections.
- `forward.py` / `prof.py`: optional CUDA-event diagnostics, disabled for throughput measurements and in shipped defaults.
- The exact running snapshot also contains the rejected FP32 atomic expert-reduction candidate and its native library/source. It is **disabled** (`prefill_atomic=false`): the local speedup did not survive the full-service 32K comparison. Do not infer that it is enabled from the original experimental image name.

Source EXLR8 K4 / MXFP8 / FP8 weights, the existing small-row MXFP8 path, FNC7:0.3 / beta 2, day-31 MSE drafter, vision, and FP8 KV are retained. No new resident expanded-weight copy is allocated. Library/workspace/driver overhead is not claimed to be zero. The observed KV pool remains 1,699,840 tokens.

All are single requests, not three-run means. Each scored request has zero cached tokens and passed the isolation check. Paired requests share prompt hashes and seed 42. The prompt uses repeated synthetic English filler followed by the Chinese prose prompt in `evidence/prompts.json`; it is not a claim about all natural workloads. Sampling is temperature 1, top-p 0.95, top-k 20, min-p 0, thinking disabled, 32 output tokens. Engine prefill throughput and client TTFT are separate metrics. A random nonce in the manual benchmark prevents prefix reuse; actual input length may vary slightly.

The 2,000 tok/s target was not reached. Atomic-on 32K measured 1,880.15 tok/s versus 1,894.71 with it off; the candidate remains disabled. No new decode or full capability evaluation was performed. These running-deployment measurements do not establish that a fresh installation of this public recipe achieves identical results.

## Numerical checks

The original geometry-only dispatch passed 34 bitwise local checks. The cuBLAS dispatch was checked on both TP slices across nine projection types and five row counts (90 cases), with maximum local relative L2 difference 0.0146566%. Whole-row versus partitioned projection execution passed 36 local checks with maximum relative L2 difference 0.0143207%. Both are below the predefined 0.1% local threshold; neither is a model-quality loss percentage. Generated output can diverge despite small matrix error. No extra weight or activation quantization was introduced by this prefill update.
